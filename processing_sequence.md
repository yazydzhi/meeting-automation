# Последовательность обработки системы автоматизации встреч

## Общая схема работы

```
🚀 ЗАПУСК СЕРВИСА
    ↓
📋 ИНИЦИАЛИЗАЦИЯ ОБРАБОТЧИКОВ
    ↓
⚙️ ЗАГРУЗКА КОНФИГУРАЦИИ
    ↓
🔄 ОСНОВНОЙ ЦИКЛ СЕРВИСА (каждые 5 минут)
```

## Детальная последовательность этапов

### ЭТАП 1: 📅 Обработка календаря (CalendarIntegrationHandler)
```
1. Получение событий календаря для личного и рабочего аккаунтов
2. Проверка, были ли события уже обработаны (StateManager)
3. Для каждого нового события:
   - Создание папки встречи в формате: "YYYY-MM-DD HH-MM Название встречи"
   - Создание файла статуса processing_status.md
   - Создание/обновление страницы в Notion
   - Сохранение информации в StateManager (SQLite)
4. Параллельная обработка личного и рабочего аккаунтов
```

### ЭТАП 2: 🎬 Обработка медиа файлов (MediaHandler)
```
1. Поиск видео файлов (.mp4, .avi, .mov, .mkv) в папках встреч
2. Проверка, не обработаны ли уже файлы (кэш + StateManager)
3. Сортировка файлов по времени создания
4. Для каждого видео файла:
   - Сжатие через FFmpeg с настраиваемым качеством
   - Извлечение аудио в MP3 формат
   - Умное именование: "название_папки_compressed.mp4"
   - Проверка длины оригинального и сжатого видео
   - Удаление оригинала при совпадении длины (если включено)
   - Сохранение информации в StateManager
5. Интервал проверки: каждые 30 минут
```

### ЭТАП 3: 🎤 Транскрипция аудио (TranscriptionHandler)
```
1. Поиск сжатых MP3 файлов (*_compressed.mp3)
2. Проверка, не транскрибированы ли уже файлы (StateManager)
3. Для каждого аудио файла:
   - Транскрипция через Whisper (модель medium)
   - Создание файла транскрипции: "название__transcript.txt"
   - Сохранение метаданных (модель, язык, время создания)
   - Сохранение информации в StateManager
```

### ЭТАП 4: 📋 Генерация саммари (SummaryHandler)
```
1. Поиск файлов транскрипции (*_transcript.txt)
2. Проверка, не созданы ли уже саммари (StateManager)
3. Для каждого файла транскрипции:
   - Генерация саммари через OpenAI API (GPT-4o-mini)
   - Создание файла саммари: "название_summary.txt"
   - Создание файла анализа: "название_analysis.json"
   - Сохранение информации в StateManager
4. Для папок с несколькими видео:
   - Создание комплексного саммари (если включено)
   - Анализ всех транскрипций в папке
   - Создание единого саммари в папке complex_summary/
```

### ЭТАП 5: 📝 Синхронизация с Notion (NotionHandler)
```
1. Поиск событий с новыми результатами обработки
2. Для каждого события:
   - Получение данных транскрипции и саммари
   - Обновление страницы Notion результатами
   - Добавление блоков с транскрипцией и саммари
   - Обновление статуса синхронизации в StateManager
```

### ЭТАП 6: 📱 Уведомления и отчеты
```
1. SmartReportGenerator:
   - Проверка изменений в системе
   - Формирование умного отчета
2. Отправка отчета в Telegram (если есть изменения)
3. Создание файлов статуса в папках встреч
4. Параллельное выполнение уведомлений и создания файлов
```

### СОХРАНЕНИЕ СОСТОЯНИЯ
```
1. StateManager:
   - Сохранение состояния цикла в SQLite
   - Обновление кэша обработанных файлов
   - Сохранение статистики производительности
2. Файловая система:
   - Кэш в data/service_cache.json
   - Состояние в data/service_state.json
   - Статистика в data/performance_stats.json
```

## Ключевые особенности

### 🔄 Параллельная обработка
- Личный и рабочий аккаунты обрабатываются параллельно
- Уведомления и создание файлов статуса выполняются параллельно

### 🛡️ Защита от дублирования
- StateManager отслеживает обработанные файлы в SQLite
- Кэш в памяти предотвращает повторную обработку
- Проверка существования файлов перед созданием

### 📊 Мониторинг и логирование
- Детальное логирование каждого этапа
- Мониторинг производительности системы
- Статистика выполнения циклов

### ⚙️ Настраиваемые интервалы
- Основной цикл: каждые 5 минут (настраивается)
- Медиа обработка: каждые 30 минут (настраивается)
- Проверка изменений для уведомлений

### 🔧 Умные функции
- Умное именование файлов на основе папки встречи
- Автоматическое удаление оригиналов при совпадении длины
- Комплексное саммари для множественных видео
- Интеллектуальные отчеты только при наличии изменений
