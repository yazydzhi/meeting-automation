# Отчет о последовательности обработки системы автоматизации встреч

## Текущее состояние системы

Система автоматизации встреч работает по четко определенной последовательности из 6 основных этапов, выполняемых в цикле каждые 5 минут.

## Основные этапы обработки

### 1. 📅 **Календарь и создание папок** (CalendarIntegrationHandler)
- **Цель**: Создание структуры для новых встреч
- **Процесс**: 
  - Получение событий из календарей (личный и рабочий аккаунты)
  - Создание папок встреч в формате "YYYY-MM-DD HH-MM Название"
  - Создание страниц в Notion для каждой встречи
  - Сохранение информации в SQLite базе данных
- **Результат**: Готовая структура для размещения материалов встреч

### 2. 🎬 **Обработка медиа файлов** (MediaHandler)
- **Цель**: Сжатие видео и извлечение аудио
- **Процесс**:
  - Поиск видео файлов в папках встреч
  - Сжатие через FFmpeg с настраиваемым качеством
  - Извлечение аудио в MP3 формат
  - Умное именование файлов на основе папки встречи
  - Автоматическое удаление оригиналов при совпадении длины
- **Результат**: Оптимизированные медиа файлы для дальнейшей обработки

### 3. 🎤 **Транскрипция аудио** (TranscriptionHandler)
- **Цель**: Преобразование аудио в текст
- **Процесс**:
  - Поиск сжатых MP3 файлов
  - Транскрипция через Whisper (модель medium)
  - Создание файлов транскрипции с метаданными
  - Сохранение результатов в базе данных
- **Результат**: Текстовые транскрипции встреч

### 4. 📋 **Генерация саммари** (SummaryHandler)
- **Цель**: Анализ и структурирование содержания встреч
- **Процесс**:
  - Анализ транскрипций через OpenAI API
  - Создание структурированных саммари
  - Генерация комплексных саммари для множественных видео
  - Сохранение результатов анализа
- **Результат**: Краткие и структурированные саммари встреч

### 5. 📝 **Синхронизация с Notion** (NotionHandler)
- **Цель**: Обновление страниц Notion результатами обработки
- **Процесс**:
  - Поиск событий с новыми результатами
  - Обновление страниц Notion транскрипциями и саммари
  - Добавление структурированного контента
  - Отслеживание статуса синхронизации
- **Результат**: Полные страницы встреч в Notion с результатами обработки

### 6. 📱 **Уведомления и отчеты** (SmartReportGenerator + TelegramAPI)
- **Цель**: Информирование о результатах работы системы
- **Процесс**:
  - Анализ изменений в системе
  - Формирование умных отчетов
  - Отправка уведомлений в Telegram (только при наличии изменений)
  - Создание файлов статуса в папках встреч
- **Результат**: Информирование пользователя о работе системы

## Ключевые особенности архитектуры

### 🔄 **Параллельная обработка**
- Личный и рабочий аккаунты обрабатываются одновременно
- Уведомления и создание файлов статуса выполняются параллельно
- Оптимизация времени выполнения циклов

### 🛡️ **Защита от дублирования**
- StateManager отслеживает все обработанные файлы в SQLite
- Кэш в памяти предотвращает повторную обработку
- Проверка существования файлов перед созданием

### 🧠 **Умные функции**
- Умное именование файлов на основе папки встречи
- Автоматическое удаление оригиналов при совпадении длины
- Комплексное саммари для папок с несколькими видео
- Интеллектуальные отчеты только при наличии изменений

### 📊 **Мониторинг и надежность**
- Детальное логирование всех операций
- Мониторинг производительности системы
- Декоратор retry для повторных попыток при ошибках
- Graceful handling исключений

## Интеграции

### Внешние сервисы:
- **Google Calendar/Drive**: Получение событий и файлов
- **Notion API**: Создание и обновление страниц
- **OpenAI API**: Генерация саммари
- **Telegram Bot API**: Отправка уведомлений
- **Whisper**: Транскрипция аудио
- **FFmpeg**: Обработка медиа файлов

### Локальные ресурсы:
- **SQLite**: База данных состояния
- **Файловая система**: Папки встреч и файлы
- **JSON кэш**: Быстрый доступ к метаданным

## Настройки и конфигурация

- **Интервал основного цикла**: 5 минут (настраивается)
- **Интервал медиа обработки**: 30 минут (настраивается)
- **Качество сжатия видео**: настраиваемое (low/medium/high)
- **Модель Whisper**: medium (оптимальный баланс качества и скорости)
- **Модель OpenAI**: GPT-4o-mini (экономичная и эффективная)

## Заключение

Система работает по четко определенной последовательности, обеспечивая:
- **Полную автоматизацию** процесса обработки встреч
- **Надежность** через защиту от дублирования и обработку ошибок
- **Эффективность** через параллельную обработку и умные алгоритмы
- **Прозрачность** через детальное логирование и отчеты
- **Гибкость** через настраиваемые параметры и конфигурацию

Все этапы интегрированы в единый цикл, обеспечивающий непрерывную работу системы автоматизации встреч.
